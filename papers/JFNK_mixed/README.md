# Benchmark cases for the mixed pressure-displacement JFNK paper

Cases, run scripts and plot scripts for every benchmark reported in

> A. Mullen-Hales, P. Cardiff and P. Castrillo,
> *Algebraically Monolithic Methods for Mixed Solid Mechanics*

Each case keeps its own `Allrun`, `Allclean`, base case, mesh definitions and
plot scripts. Every case `Allrun` performs

```text
case and mesh generation -> simulation -> result extraction -> plots in the manuscript style
```

and the plots are always drawn from the results of that run. The scripts in
this directory

1. run each case's own `Allrun` with the mesh sequence used in the paper,
2. check that every expected figure was produced by that run and copy the
   figures into `figures/`, and
3. assemble them into a single PDF with a heading above the figures of each
   test case.

No simulation result is stored in this repository. The published figures and
the data behind them are regenerated by the separate paperData package, which
does not read anything from here; the two routes are independent (see
`plotStyle/README.md`).

## Commands

Source the OpenFOAM and solids4foam environment first (see Requirements).

### Full paper campaign

```bash
./Allrun              # all eight cases with the paper mesh sequences
./AllrunTest          # the same workflow on the first one or two meshes
./Allclean            # remove every generated run, table, figure and log
```

`./Allrun` is serial and long: the finest ventricle and nonlinear Cook's
meshes take hours each. A failing case is reported and the run continues;
`./Allrun --stop-on-error` stops at the first failure.

### One benchmark, or selected meshes

```bash
./Allrun --list                          # cases and the mesh sequence each uses
./Allrun fourier                         # Fourier verification only
./Allrun mms beam                        # only the named cases
BEAM_MESH_LEVELS="2 3 4" ./Allrun beam   # beam: explicit mesh levels
```

For other mesh selections use the case script directly; each has `--help`:

```bash
(cd linearElastic/manufactoredSolution && ./Allrun 3)             # meshes 1-3
(cd linearElastic/cooksMembrane && ./Allrun structured)           # one study: structured | parameter | unstructured
(cd hyperElastic/cooksMembrane && ./Allrun 4)                     # meshes 1-4
(cd hyperElastic/LargeStrainIncompCooksMembrane && ./Allrun 5)                 # meshes 2-5 (START_MESH=1 to include mesh 1)
(cd hyperElastic/ventricle/beam && MESH_LEVELS="2 3" ./Allrun)
(cd hyperElastic/ventricle/inflation && MESH_LEVELS="2 3" ./Allrun)
(cd hyperElastic/ventricle/contraction && MESH_LEVELS=1 ./Allrun)
```

The beam, inflation and contraction cases refuse to overwrite an existing
`runs/meshN` directory, and the linear Cook's membrane case refuses to
overwrite an existing campaign; run `./Allclean` (here or in the case) before
repeating a run.

### Fourier verification

```bash
./Allrun fourier
# or, in the case directory:
(cd fourierVerification/pressureStabilisationFourier && ./Allrun)
```

Meshes N = 16, 32 and 64, the `stabilisationFourierCheck` utility, the result
check (`checkResults.py`), the table of maximum errors
(`postProcessing/paperFigures/fourier_max_errors.txt`) and Figure 1. No solver
is involved and the run takes seconds.

### Without plots

```bash
./Allrun --no-plots              # same as PLOTTER=none ./Allrun
PLOTTER=none ./Allrun inflation
```

The cases are generated, run and extracted; no figure is drawn and the summary
lists them as `NO PLOTS`.

### Extract and plot existing results (no solver)

```bash
./Allrun --plots-only            # plot the tables each case has already extracted
./Allrun --extract               # re-extract from the completed runs, then plot
./Allrun --plots-only mms beam   # for selected cases
./Allrun --figures-only          # only re-collect existing figures and rebuild the PDF
```

`--plots-only` needs Python only. `--extract` rebuilds the result tables from
the solver logs and function-object output of the completed cases; for the
inflation and contraction cases it runs `extractIdealisedVentricleResults`, so
those two need the OpenFOAM environment. The same stages exist in every case
script:

| Case | Plot existing tables | Re-extract, then plot |
|---|---|---|
| Fourier | `./Allrun plots` | the same (the utility writes the CSV files directly) |
| Manufactured solution | `./Allrun plots [run_dir]` | `./Allrun extract [run_dir]` |
| Linear Cook's | `./Allrun plots` | `COOKS_HPC_DATA_DIR=$PWD/runs/full ./Allrun plots` |
| Nonlinear Cook's (both) | `./Allrun plots [run_dir]` | `./Allrun extract [run_dir]` |
| Beam, inflation, contraction | `./Allrun plots` | `./Allrun extract` |

`run_dir` defaults to the newest `run_*` directory of the case.

### Batch systems

No script in this directory submits a job. To use a scheduler, run an `Allrun`
inside the job: extraction and plotting then follow the simulations in the
same job and only if they succeeded.
`linearElastic/cooksMembrane/run.slurm` is such a job script. If a job runs the
simulations only (`PLOTTER=none`), make the figures afterwards with
`./Allrun --plots-only`; nothing is plotted merely because a job was
submitted.

## Status and failures

The summary printed at the end, and the exit status, distinguish

| Status | Meaning |
|---|---|
| `OK` | the case finished and every expected figure was written by this invocation |
| `FAILED` | the case script returned an error (failed mesh, solver, extraction or plot); its figures are not collected |
| `INCOMPLETE` | an expected figure is missing, or the figures were drawn from fewer meshes than the selected mode requires |
| `NO PLOTS` | plotting was disabled |

The exit status is non-zero when any case is `FAILED` or `INCOMPLETE`. A figure
left over from an earlier run is never counted: only figures written after the
case started are collected. Case scripts stop when an input is missing, when a
solver log did not reach `End` and, for the ventricle cases, when a load
increment did not converge. A curve is never left out without an error or an
`INCOMPLETE` message. Results outside the fixed axis window of a published
figure, and data hidden by a legend, are reported as warnings.

Mesh sequences of the full run:

* **Manufactured solution**: five meshes, spacing 40 mm halved to 2.5 mm, as
  plotted in Figures 3 to 5. The case defines a sixth mesh
  (`./Allrun 6` in the case directory); it lies outside the axis window of the
  published figures and is reported as such when plotted.
* **Linear Cook's membrane**: six meshes, `3x3` to `96x96` cells in plane.
* **Nonlinear Cook's membrane**: meshes 1 to 8 for nu = 0.3 and meshes 2 to 8
  for nu = 0.4999, as in Figures 10(b) and 11.
* **Heart tissue beam**: mesh levels 2 to 6 (cell sizes 0.5 mm to 0.03125 mm).
  Level 1 (10 cells) is not part of Figure 13.
* **LV inflation**: three meshes, 1,620 / 12,960 / 103,680 control volumes,
  solved quasi-statically (`d2dt2Schemes default steadyState`,
  `ddtSchemes default backward`).
* **LV active contraction**: three meshes, 3,240 / 25,920 / 103,680 control
  volumes.

### Figures 15 and 16 over the published Land et al. (2015) results

The inflation and contraction scripts write the data layer of these figures
(`land_problemN_m3_combined_layer.pdf`) and place it over faint crops of the
published Land et al. (2015) result figures
(`land_problemN_m3_combined_overlay.pdf`). The crops are in
`hyperElastic/ventricle/referenceData/`, with their attribution; they hold the
published curves only, so a composite shows no results other than those of the
run being plotted. `LAND_OVERLAY_PDF=none` writes the data layer only. The
composite needs the Python package `pypdf`.

### Field-image panels and static illustrations

`./Allrun` produces the numerical plots only. It never copies an archived image
into its output.

* Field panels, Figures 2(b), 10(a) and 14(b): rendered from a completed case
  of this checkout with ParaView, as a separate step:

  ```bash
  scripts/renderFieldPanels mms       linearElastic/manufactoredSolution/run_<...>/poly.hypre.3
  scripts/renderFieldPanels cooks     hyperElastic/cooksMembrane/run_<...>/hex_snes__evenlap_m2.7
  scripts/renderFieldPanels inflation hyperElastic/ventricle/inflation/runs/mesh3
  ```

  The panels are written to `figures/fieldPanels/`. Camera, slice or clip and
  colour range are those of the published panels; see the head of the script.
  The cases need their fields: the manufactured-solution and nonlinear Cook's
  runs write them at the final time, the ventricle runs every 0.1.
* Figure 12(b), the deformed beam: the published panel was exported by hand
  and there is no scripted view; which mesh it shows is not recorded. It has
  to be redrawn by hand in ParaView from a completed beam case (for example
  `hyperElastic/ventricle/beam/runs/mesh6`, time 1): warp by `D` with scale 1
  and colour by the magnitude of `D`; the published colour bar spans 0 to
  3.2 mm.
* Static illustrations (geometry drawings and mesh screenshots: Figures 2(a),
  6, 9(a), 12(a), 14(a)) are not generated here; they are in paperData.

## Output

```text
figures/
|-- 01_fourier/                         # copies of each case's figures
|-- 02_mms/
|-- ...
|-- fieldPanels/                        # only after scripts/renderFieldPanels
|-- manifest.tsv                        # heading and caption of every figure
`-- JFNK_mixed_paperFigures.pdf         # all figures, grouped under headings
logs/
`-- <case>.log                          # console output of each case
                                        # (<case>.plots.log, <case>.extract.log)
```

Each case also keeps its figures where it wrote them (last column of the
workflow table) together with a `*_series.json` file that records the arrays
handed to the plotting library. The combined PDF is built by
`scripts/combineFigures.py`. It uses `pdflatex` when available, which keeps the
figures vector, and otherwise falls back to rasterising them with Ghostscript
and laying them out with ReportLab.

## Requirements

* A configured OpenFOAM environment (the paper runs used OpenFOAM v2312) and a
  solids4foam build with PETSc/SNES support that contains the spectral
  normalisation of the pressure stabilisation and the
  `stabilisationFourierCheck` utility. These are in
  `solids4foam/solids4foam` on the `fix-pressure-solid` branch at commit
  `12059d360780aab125d36170331c9c7d68b0ade2` (pull request 462). The paper runs
  used the `pr/spectral-normalisation` branch at commit `1bd89e5d`, which has
  the same source tree.
* Case-local utilities. `extractIdealisedVentricleResults` (inflation and
  contraction; links `libsolids4FoamModels`) and `setLand2015FibreField`
  (contraction; OpenFOAM only) are built by the case `Allrun` scripts when
  they are not on `PATH`. The `manufacturedSolution` library is built by hand
  before running the manufactured-solution case; see
  `linearElastic/manufactoredSolution/README.md`.
* `gmsh` for the polyhedral and unstructured mesh families.
* For the plots: `python3` (3.9 or later) with `numpy`, `matplotlib` (3.8 or
  later) and, for the ventricle figures, `reportlab` and `pypdf`; `pillow` for
  the field panels. `PLOT_PYTHON` selects the
  interpreter (`COOKS_PLOT_PYTHON` for the linear Cook's case). The figures of
  the paper were drawn with Python 3.13, matplotlib 3.11 and numpy 2.5.
* Optional: poppler `pdffonts` (the style then checks that fonts are embedded);
  the macOS Helvetica font (other systems fall back to Arial, Liberation Sans
  or DejaVu Sans, which changes text widths but no number); `gnuplot` for the
  earlier gnuplot plotters (`PLOTTER=gnuplot` in a case script).
* `pdflatex` for the vector combined PDF, or Ghostscript and ReportLab for the
  raster fallback.
* Field panels only: ParaView 5.13 `pvpython` (`PVPYTHON=/path/to/pvpython`).

## Conventions and scope

* The manuscript indexes the coupled even-order Laplacian family by
  `m = laplacianPower`: `m = 0` Laplacian, `m = 1` bi-Laplacian, `m = 2` sixth
  order. Run names such as `evenlap_m2` already carry `laplacianPower`. Figure
  and script file names containing `m1`, `m2` or `m3` keep an earlier
  one-based tag, so `m3` in a file name is the manuscript's `m = 2`.
* The styled plot scripts and `plotStyle/paper_figure_style.py` were copied
  from the paperData package. `plotStyle/README.md` lists the sources, the
  changes made here and how to keep the two copies in step
  (`scripts/checkPlotSync.py`).
* This directory holds case set-ups and the scripts that run and plot them.
  Simulation results are not stored here: `run_*/`, `runs/`, `results/`,
  `figures/`, `plots/`, `postProcessing/` and `logs/` are generated and ignored
  by Git. Small published reference tables used by the plots are kept, with
  their origin, in `plotStyle/README.md`.
